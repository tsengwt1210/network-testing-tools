# NV Band Preference Center

主要入口：[`tools/nv/nv_band_preference_tool.py`](../tools/nv/nv_band_preference_tool.py)。

## 操作

1. 執行主程式，在上方選擇 4G／5G 或 3G／4G 分頁，再選左側 NV 項目。
2. 在頻段欄輸入清單，例如 `1, 3, 7, 8, 20, 28, 38`，計算各欄位數值。
3. 也可輸入十進位或 `0x` 十六進位值，執行反向解碼，再比對頻段清單。
4. 詳細頁提供十進位、十六進位、二進位、位元定位明細、PCAT 文字複製與 CSV 匯出。修改輸入後，先執行相應的計算或解碼，使兩側一致，再匯出。

清單解析接受逗號、空白、分號及區間，例如 `1-3, 7, 8`；重複項目會合併。數值必須落在 Uint64 範圍 `0` 至 `18446744073709551615`。

## 程式內設定

以下是程式內的設定表，不是通用 modem 規格表。

| NV ID | 程式中的標示 | 詳細頁欄位數 | 可表示的位置 |
| --- | --- | --- | --- |
| 65633 | LTE Band Preference | 1 | 1–64 |
| 74087 | NR5G SA Band Preference | 5 | 1–320 |
| 74213 | NR5G NSA Band Preference | 5 | 1–320 |
| 6828 | LTE Band Preference | 1 | 1–64 |
| 1877 | WCDMA Band Preference | 1 | 1–64 |
| 4548 | WCDMA/GSM Band Preference | 1 | 1–64 |

NR 的 Overview 快速區只顯示前兩個 Uint64（1–128）；要示範第 277 個位置，需開啟 74087 或 74213 的詳細頁。可表示某個位置，不代表設備或通訊標準支援同號頻段。

## 可手算的例子

程式以第 `n` 個位置對應第 `n - 1` 個 bit；每 64 個 bit 為一組。欄位索引從 0 開始：

```text
group_index = (n - 1) // 64
bit_offset  = (n - 1) % 64
value       = 1 << bit_offset
```

同一組內的值以 bitwise OR 合併。`1, 3, 7, 8` 對應 `1 + 4 + 64 + 128 = 197`，十六進位為 `0x00000000000000C5`。

| 位置 | 欄位 | 該欄位內的位元（從 1 起） | 欄位值 |
| --- | --- | --- | --- |
| 64 | bits_1_64 | 64 | 9223372036854775808 |
| 65 | bits_65_128 | 1 | 1 |
| 277 | bits_257_320 | 21 | 1048576 |

因此，在 5 個欄位只設定位置 277，結果為 `[0, 0, 0, 0, 1048576]`。這是位元換算範例；它不表示已驗證某裝置支援 n277。

## 閱讀程式的順序

先讀 `parse_bands()` 與 `parse_integer()` 看輸入如何驗證，再讀 `encode_bands()`、`decode_values()`、`mapping_detail()`。`NVDefinition` 和兩組 NV 設定表決定各頁的欄位數與顯示資訊；`B45_NVPage`、`B34_NVPage` 負責與 Tkinter 介面串接。

現有設計保留兩個相近的頁面類別，仍有重複的介面程式碼。本次整理優先維持原有操作方式，沒有將整個 GUI 重構成通用頁面。

## 平台限制

工具沒有讀取裝置、識別晶片平台或寫入 NV 的程式。它也沒有依 3GPP 的實際頻段清單限制輸入；尤其 WCDMA／GSM 的 NV 位元定義可能不是 `n - 1`。設備上的 NV ID、位元定義及 PCAT 格式須另行核對，純函式測試只能證明目前程式規則的換算一致性。
